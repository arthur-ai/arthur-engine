## Decisions Made
- Plan said to use `cast(DatabaseDatasetVersionRow.id, Text).ilike(search_term)` directly. That works in production PostgreSQL (cast → canonical hyphenated UUID) but FAILS in the unit test, which runs on SQLite where `sqlalchemy.UUID` is stored as a bare 32-char hex string (no hyphens). Verified experimentally.
- To be dialect-robust AND pass the SQLite test, normalized hyphens on both sides: `func.replace(cast(id, Text), "-", "").ilike("%" + search.replace("-", "") + "%")`. Works in Postgres and SQLite, and also lets users paste the ID with or without hyphens. Minimal deviation from plan, preserves its intent.
